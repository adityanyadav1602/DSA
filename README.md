This repository reflects rigorous Computer Science fundamentals (GATE CS & LeetCode), emphasizing optimal time-complexity bounds, memory management, and clean object-oriented architecture.

---

## 📂 Repository Structure & Topics

### 1. Linked Data Structures (/)
Implementations of fundamental dynamic memory abstractions, pointer manipulation, and traversal algorithms:
- create_node.py & create_SLL.py: Singly Linked List (insertion, traversal, edge-case handling).
- create_DLL.py & notherDLL.py: Doubly Linked List with bidirectional pointer management.
- link_list.py & 
eversLL.py: Iterative in-place pointer reversal ((N)$ Time, (1)$ Space).

### 2. Algorithmic Problem Solving & LeetCode (/)
Optimal solutions to classic algorithmic challenges:
- 3Sum.py: Two-pointer technique on sorted arrays ((N^2)$ optimal approach).
- Median_twoSortedArry.py: Advanced binary search partition ((\log(\min(M, N)))$ time complexity).
- longest_Substring.py: Dynamic sliding window pattern for substring tracking.
- ddtwoNum.py: Linked list arithmetic handling multi-digit carry propagation.
- MaxProductofthreeNum.py: Linear scan greedy evaluation ((N)$).
- 
everse_string.py & 
everse_num.py: In-place two-pointer manipulation and arithmetic digit extraction.

### 3. Object-Oriented Programming & Python Internals (OOPs_code/)
Advanced Python object models, memory allocation mechanics, and polymorphic patterns:
- __new__.py: Python object allocation lifecycle and Singleton design pattern implementation.
- Duck_typing.py: Dynamic polymorphism and protocol adherence in Python.
- school_sys.py & create_class.py: Encapsulation, inheritance hierarchies, and domain modeling.

## ⚙️ Engineering Principles Followed

- **Algorithmic Complexity:** Documented Big-O Time & Space complexities for every pattern.
- **Pointer Safety:** Thorough boundary checks for null pointers, single-element structures, and empty inputs.
- **Pythonic Idioms:** Proper utilization of Python data model, magic methods (__init__, __new__, __str__), and type annotations.
